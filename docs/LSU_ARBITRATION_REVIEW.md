# LSU 仲裁第一輪：功能結果與取捨

2026-11-16（Asia/Taipei）整理；實測於 2026-11-13 完成，乾淨來源 `669c8ee`。
**完整功能與 27 項週期量測通過，但這版交換了兩類效能：FP32 改善、Embench 小幅退步。**
尚未升格基線，也尚未進行候選的實體時序／面積資格。

後續 [唯讀逐拍診斷](LSU_ARBITRATION_DIAGNOSIS.md)已完成：確認讓行 store 的兩拍代價、
FFT／statemate 額外被取消的讀取，並提出 ROB 空間限制；以下保留第一輪完整量測。

## 實作與比較契約

以完成資格的 A+B `49122fb` 為父版本，只修改 LSU：首次 head-store marking 時，
若已有通過相依檢查的外部 load，讓它先送一次；之後沿用 SQ 的 marked 位恢復 store 優先。
新增一個 load 選擇保留位，確保回壓時不切換已送出的請求。記憶體忙碌時可能直接耗掉
首次機會；這不是任意輪替、無限制 load 優先，或依工作負載 PC 特判。

單一外部 outstanding、相依／轉送檢查、registered response 交接、精確 fault／flush、
store 成功回應後退休都保留。沒有修改 FPU、divider、C 前瞻或記憶體服務政策。
ELF、逐 PC 退休工作量、I response／I interval／D response 的固定 10,000 ps 均維持。

## 已知改善與退步的位置

- **PID：8,256 → 7,238（−12.3304%）**。相對獨立 A 的 7,242，也少四拍。
  互斥分類差額為 store ack +1,022、FMA 頭端 −1,020、FADD −510、FP store 頭端 −510，
  正好合計 −1,018。父版本的 waveform 機制已知；本輪沒有重新宣稱候選全迴圈 VCD 證明。
- **FFT：33,656 → 34,851（+3.5506%）**。store ack 增加 2,635，INT／FP load 頭端等待
  分別減少 1,085／268，其他差額合計 −87，總計 +1,195。
- **statemate：2,614,289 → 2,805,791（+7.3252%）**。store ack 增加 255,328，
  INT load 頭端等待少 67,757，其餘分類合計 +3,931，總計 +191,502。
- **Cholesky：+0.5713%**。load 頭端等待減少，但 store ack 增加，整體仍較慢。

所有 54 份父／候選 profile 的互斥差額已與總週期逐項核對。這些分類描述退休當時的等待位置，
不能相加當成獨立可刪除的 cycles，也尚未證明 FFT／statemate 的完整相依鏈根因。

## 驗證、來源與限制

- 實際 A+B／候選 RTL 各 **140 項** pin-driven 測試，含 66 個原安全案例、74 個仲裁案例。
- 三個 RTL 負向對照都能被拒絕：父版假冒新策略、無限制 load 優先、取消回壓選擇保留。
- 乾淨 normal／assert 模型；18 directed、18 Spike、48 介面、58 記憶體、3,400 有限 FMA 檢查通過。
- 全 27 項、3,629 筆數值、ELF／memory audit／per-PC 工作量與來源綁定審查通過。
- 建置、功能資格、量測各階段的來源皆為乾淨 `669c8ee`，開始與結束相同；外層控制器各階段實際 exit 0。
- 契約四項及 provenance 九項控制通過；原基線、其他 CPU RTL、模擬與評分政策保持不變。
- 首次單元控制器預期 SVA 訊息，但既有 pin-driven 檢查先拒絕了無限制優先 mutant，導致訊息比對失敗。
  修正預期失敗訊息後，以新目錄重跑全套；原失敗與當時 checker 保留，沒有修改 RTL 以略過失敗。

[本輪證據](evidence/2026-11-16/lsu-arbitration-functional/README.md)保留原始模型、完整測試／量測、
父版本參照、失敗控制器與時序原報告。完整 ISA／IEEE-754 及候選 PPA 都是另外的資格範圍。

## 目前 critical paths 與建議下一步

[Critical-path 清單](CRITICAL_PATHS.md)核對父版本三個 corner、兩個週期，共 240 條抽樣報告。
SS／9.4 ns 最緊是 **INT EX0 → dmem 位址 +8.20 ps**，FPU 算術到 completion **+59.46 ps**；
FF 最緊 hold 是 ROB event counter → commit trace，**+17.58 ps**。
這些是 A+B 的已測值，不是新仲裁的 PPA。新選擇邏輯在 LSU 敏感路徑附近，必須重新量測才能判定代價。

**逐拍診斷已完成，建議共同審查 [ROB 空間限制方案](LSU_ARBITRATION_DIAGNOSIS.md)。**
目前沒有證據支持把「所有安全 load 一律值得先送」當成跨集合的最佳策略。
也可選擇先完成此版實體資格，或保留 A+B 改做 C；取捨由使用者共同決定。
本輪不自動改目標、放寬案例、擴大 outstanding 或升格基線。
